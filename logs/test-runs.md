# Test runs

A short, consistent record per real task run through forge-guide - meant to be filled in
right after a run while it's fresh, and easy to hand off for review. Append one entry per
run; don't edit past entries except to add a resolution note once something's fixed.

Keep each entry short - a few lines per section, not a transcript. If a section doesn't
apply to this run, write "n/a" rather than leaving it blank (blank looks like it was
forgotten, not that it didn't apply).

---

## Run template (copy this per run)

```markdown
### Run <N> - <date> - <one-line task description>

**Spec:** `specs/<folder>/spec.md` (link or path)
**Skill used:** new-feature | bug-fix | refactor | api-integration | spec-builder

**What worked:**
- <a step, check, or mechanic that actually helped - be specific about which one>

**What broke or felt like friction:**
- <where the workflow got in the way, asked something useless, missed something it
  should've caught, or the gate blocked/passed something wrongly>

**Clarification round:** <how many questions, were they the right ones, anything you
had to answer that the context scan should have already found itself>

**Quality gate outcome:** <what fired - severities, any suppressions used and why>

**Token-ledger delta:** <link to the logs/token-ledger.md entry for this run, or the
numbers directly - clarification rounds, any full-file regeneration>

**One thing to fix before the next run:**
- <the single highest-value change - not a wishlist, just the one thing>
```
